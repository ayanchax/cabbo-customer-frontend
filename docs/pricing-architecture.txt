# Cabbo Pricing Architecture

Last Updated: September 9, 2026

Cabbo uses geography-based pricing with different commercial contracts for each trip domain. Airport transfers, local hourly rentals, and outstation trips have different customer expectations and different driver economics, so they should not be forced into one universal formula.

## Core Principle

Cabbo sells the service category, not the fuel type.

Customer-facing pricing and selection:

```text
geography x trip type x cab type
```

Operational fulfilment:

```text
cab type x available vehicle x driver eligibility x fuel type
```

Fuel type remains useful operational data, but it is no longer a customer-facing product dimension and no longer part of pricing identity.

## Why Fuel Is Not Customer-Facing

Fuel type is an operational attribute. Customers primarily care about:

- Cab category and capacity
- Clear upfront fare
- Reliability and comfort
- Whether the promised cab category arrives

Showing separate options such as Sedan Petrol, Sedan Diesel, and Sedan Hybrid creates artificial products. Customers naturally choose the cheapest fuel option, demand gets concentrated on that fuel type, and assigning a different fuel vehicle later feels like a substitution even when the customer experience is equivalent.

Cabbo now shows one option per eligible cab type:

```text
Sedan
Sedan Plus
SUV
SUV Plus
```

Cabbo may fulfil a booked Sedan using petrol, diesel, hybrid, CNG, or eventually EV inventory, provided the assigned vehicle matches the promised cab category and service quality.

## Fuel Data Still Exists

Fuel type should remain in:

- Fuel master data
- Driver profiles
- Vehicle records
- Assignment and operations logic
- Actual fulfilled trip metadata

Fuel type should not be used for:

- Customer ride option labels
- Customer ride search filtering
- Customer-facing price identity
- Booking hash identity for new searches
- Best-choice recommendation
- Upgrade/downgrade wording

Future EV handling should follow the same rule: do not sell "EV Sedan" as a normal ride option. If an EV is assigned, Cabbo can later show it as a post-booking benefit, such as estimated CO2e avoided, using actual trip distance and a documented baseline.

## Geography Hierarchy

```text
Country
  - Currency
  - Platform fee tax
  - Fixed platform fee

State
  - Outstation pricing
  - Interstate permit fees
  - State-level distance/day guardrails
  - Night allowance configuration where applicable

Region
  - Local hourly rental pricing
  - Airport pickup/drop pricing
  - Local package configuration
  - Airport toll/parking/placard configuration
```

## Pricing Tables

### LocalCabPricing

Used for local hourly rentals.

- Geography: `region_id`
- Granularity: cab type + region
- Unique identity: `region_id, cab_type_id`
- Main fields:
  - `hourly_rate`
  - `overage_amount_per_hour`
  - `overage_amount_per_km`
  - `is_available_in_network`

Local pricing is not route-distance pricing. The package is sold by time, with included kilometers acting as a usage boundary.

### AirportCabPricing

Used for airport pickup and airport drop.

- Geography: `region_id`
- Granularity: cab type + region
- Unique identity: `region_id, cab_type_id`
- Main fields:
  - `fare_per_km`
  - `overage_amount_per_km`
  - `is_available_in_network`

Airport trips are priced upfront from the estimated route distance:

```text
billable_km = max(estimated_route_km, min_included_km)
base_fare = billable_km x fare_per_km
total_price = base_fare + selected toll + parking + placard + platform fee
rate_per_km = base_fare / billable_km
```

`max_included_km` may exist in shared config but is not used as an airport billing cap. Extreme airport-looking trips are routed to the correct domain by trip classification and distance validation.

Normal airport pricing does not show route-distance overage warnings. The route distance is already priced into the upfront fare.

### OutstationCabPricing

Used for outstation/intercity trips.

- Geography: `state_id`
- Granularity: cab type + state
- Unique identity: `state_id, cab_type_id`
- Main fields:
  - `base_fare_per_km`
  - `driver_allowance_per_day`
  - `min_included_km_per_day`
  - `overage_amount_per_km`
  - `is_available_in_network`

Outstation pricing is a day/km package:

```text
included_km = min_included_km_per_day x total_trip_days
base_fare = base_fare_per_km x included_km
driver_allowance = driver_allowance_per_day x total_trip_days
total_price = base_fare + driver_allowance + permit_fee + platform fee
rate_per_km = base_fare / included_km
```

Extra kilometers, extra days, tolls, paid parking, and night charges are actuals when incurred. They are not folded into the initial payable fare.

### PermitFeeConfiguration

Used for interstate outstation trips.

- Geography: `state_id`
- Granularity: cab type + state
- Unique identity: `cab_type_id, state_id`
- Permit fees are configured as weekly state-level fees per cab type.
- Permit fee applies when the route crosses configured state borders.

### CommonPricingConfiguration

Common pricing config is trip-type specific and scoped by geography.

For airport/local:

- Geography: `region_id`
- Holds platform fee percent, airport toll, airport parking, placard charge, platform fee caps, and booking-window rules.

For outstation:

- Geography: `state_id`
- Holds platform fee percent, distance/day guardrails, booking-window rules, and overage warning thresholds.

### TripPackageConfig

Used for local hourly rental packages.

- Geography: `region_id`
- Granularity: trip type + region + package
- Main fields:
  - `included_hours`
  - `included_km`
  - `package_label`
  - `driver_allowance`

Examples:

- 4H / 40KM
- 6H / 60KM
- 8H / 80KM
- 10H / 100KM
- 12H / 120KM

### FixedPlatformPricingConfiguration

Used for country-level fixed platform fee.

- Geography: `country_id`
- Combined with dynamic platform fee percentage.
- In the v2 platform-fee calculation, the fixed fee plus dynamic percentage is treated as the real platform fee base.
- `max_platform_fee` is enforced as the customer trust guardrail for high-value trips.
- `min_platform_fee` remains available in config for legacy compatibility, but v2 does not use it to push low-value trips upward.
- The base platform fee is rounded before tax using the 9-ending pricing rule.
- Platform fee tax is calculated after the base platform fee is finalized; the final tax-inclusive amount does not need to end in 9.

Current India seed direction:

```text
fixed_platform_fee = INR 65

Platform fee v2:
raw_fee = fixed_platform_fee + (dynamic_platform_fee_percent x total_price_before_platform_fee)
after_cap_fee = min(raw_fee, max_platform_fee) when max_platform_fee is configured
platform_fee_base = round_fee(after_cap_fee)
platform_fee = platform_fee_base + applicable platform fee tax
```

## Unified Price Selection

The old seed data had fuel-specific prices. The unified cab-level seed price is chosen as the upper median of the old fuel-specific values for the same geography, trip type, and cab type.

Example:

```text
Sedan old rates: CNG 23, Diesel 24, Petrol 25
Unified Sedan rate: 24
```

This is intentionally not the cheapest rate. It protects fulfilment when Cabbo assigns petrol or diesel inventory, while staying close enough to market pricing for conversion.

BLR/Karnataka review after migration:

- Airport Sedan at INR 24/km is acceptable for BLR airport transfers.
- Local Sedan at INR 280/hour is aligned with 8H/80KM market pricing.
- Outstation Sedan at INR 12/km plus INR 400/day driver allowance is competitive.
- SUV Plus at INR 20/km outstation is acceptable when mapped to premium SUV/Crysta-like supply.

The current BLR/Karnataka numbers are good enough to keep. Do not reduce them just because hybrid/CNG was previously cheaper.

## Domain Semantics

### Airport

Airport pricing should feel like a clean fixed quote for the selected estimated route.

- Bill full estimated route km, subject only to a minimum billable km floor.
- Do not cap billable km at `max_included_km`.
- Include toll only when customer selects the airport toll-road preference.
- The included toll-road charge covers the standard airport toll for the selected route only.
- Additional toll gates caused by route changes, detours, or extra stops are paid as actuals.
- Pickup parking can be included when configured.
- Drop parking is currently zero.
- Placard is pickup-only and only when requested.
- Airport `rate_per_km` is computed from base fare, not total fare.

### Local Hourly Rental

Local rental is a time package.

- Price by selected package hours.
- Included kilometers define the usage allowance.
- Overage applies for extra time and extra kilometers.
- No advance toll/parking balance hold exists.
- Tolls and paid parking are actuals if incurred.
- `rate_per_min` is the meaningful product-facing rate.
- `rate_per_km` remains in the API shape only for schema consistency and is not product-facing.

### Outstation

Outstation is a day/km package.

- Included kilometers are calculated from total trip days.
- Driver allowance is charged per day.
- Interstate permit fee is added per cab type when configured states are crossed.
- Overage warning is shown when estimated route km is close to or above included km.
- Extra km, extra days, tolls, paid parking, and night driving charges are actuals if incurred.
- Outstation `rate_per_km` is computed from base fare, not total fare.

## Availability Rules

Availability is controlled by `is_available_in_network` on pricing rows plus active flags on cab master data.

Current launch direction:

- Hatchback rows may exist for future use but should not be customer-prominent unless supply quality is reliable.
- Best-match chooses the closest eligible car type by rank, then price.
- Fuel availability does not decide whether a customer-facing ride option appears.
- Assignment may still consider driver vehicle fuel type internally if operations needs it.

## Calculation Examples

### Local 4H / 40KM

```text
package = 4H / 40KM
base_fare = hourly_rate x 4
total_price = base_fare + driver_allowance + platform fee
rate_per_min = total_price / 240
```

Trip-end actuals may include extra time, extra km, tolls, or paid parking.

### Airport Transfer

```text
estimated_route_km = 54
billable_km = max(54, min_included_km)
base_fare = billable_km x fare_per_km
total_price = base_fare + selected standard airport toll + parking + placard + platform fee
rate_per_km = base_fare / billable_km
```

No distance overage warning is needed because route distance is priced upfront.

### Outstation 2-Day Trip

```text
included_km = 300 x 2
base_fare = included_km x base_fare_per_km
driver_allowance = 2 x driver_allowance_per_day
total_price = base_fare + driver_allowance + cab-specific permit_fee + platform fee
rate_per_km = base_fare / included_km
```

Actuals can apply for extra km, extra days, tolls, paid parking, and night driving.

## Operational Notes

- Booked trips should preserve their quoted pricing values for auditability.
- Future pricing changes should affect new searches/bookings, not old booked trips.
- Admin screens should expose cab-level pricing rows, availability toggles, package configs, platform fee config, permit fees, night config, fuel master data, and cancellation policies.
- Fuel master data remains admin-editable for operations and driver/vehicle metadata.
- Pricing changes should be auditable by actor and timestamp.
- Future dynamic toll APIs should not be part of the core airport fare path unless operations can handle assignment-time route changes and payment recalculation cleanly.
